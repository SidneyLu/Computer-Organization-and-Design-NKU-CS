\section{实验目的}
通过本实验，读者应完成以下目标：
\begin{enumerate}
    \item 理解 Query-Key 点积在缩放点积注意力中的作用，并明确本实验只研究点积内核，不扩展到 softmax、多头或 Value 加权。
    \item 掌握如何分别用 ARMv9-A / AArch64 与 RV64IM 汇编实现同一个点积循环，并在相同输入下验证功能一致性。
    \item 掌握 ARMv9-A 在“不使用 SVE2（标量）”与“使用 SVE2（向量）”两种实现路径下的实验对比方法。
    \item 学会在 WSL + QEMU User 环境下完成编译、运行、反汇编和批量计时。
    \item 明确本实验只聚焦\textbf{单一代表性差异}：核心循环的代码密度（每轮静态指令数与循环体字节数）。
    \item 理解“静态指令数更少”、“当前模拟平台上测得更快”、“真实平台上运行更快”并不是等同的概念。
\end{enumerate}

\subsection{面向授课对象的实验结论设定}
本实验以“给其他同学上一次可复现实验课”为目标，预设希望读者最终独立得到以下结论：
\begin{enumerate}
    \item ARMv9-A（AArch64）与 RV64IM 在实现同一乘加循环时，代码组织方式不同；
    \item 在本实验工作负载中，ARMv9-A 核心循环的代码密度更高（循环更短）；
    \item ARMv9-A 在当前 QEMU User 6.2.0 环境中，“使用 SVE2”不一定比“标量实现”更快；
    \item 时间测量结果可作为补充观察，但不替代“单一差异点”的核心结论。
\end{enumerate}

\section{问题描述与应用场景}
\subsection{Q-K点积}
Transformer 中最常见的注意力打分步骤可以抽象为 Query 向量与 Key 向量的点积。若只保留最核心的一步，则可以写成：
\[
    score = \sum_{i=0}^{N-1} q_i \times k_i
\]
这里的 $score$ 可以看作缩放点积注意力中未归一化的相关性分数。真实模型中还会继续执行缩放、softmax 和对 $V$ 的加权，但这些步骤会引入额外控制流与浮点计算，不利于把实验重点稳定地压缩到“点积循环如何用不同 ISA 表达”这一问题上。

本实验选取 Query-Key 点积作为实验对象，有三点原因。第一，它保留了注意力机制中最核心的乘加循环，具有明确的实际应用背景。第二，它同时包含顺序访存、乘法和累加，足够体现 ISA 在循环表达上的差异。第三，它可以被压缩为一个很小的汇编内核，便于使用反汇编工具准确锁定核心循环位置，并在扩大数据量后继续保持分析目标清晰。

因此，本实验关注的是同一个点积内核在 ARMv9-A 与 RISC-V 上的实现方式，以及在统一输入、统一 QEMU 环境下观察到的代码密度与运行时间结果。

\subsection{ARMv9-A}
ARM（Advanced RISC Machine）是一种基于精简指令集（RISC）的高效能、低功耗处理器架构，
广泛应用于移动设备、嵌入式系统和服务器领域。ARMv8开始引入64位处理能力，苹果的A7芯片率先采用了该版本。
而ARMv9-A 是 ARM 最新的应用处理器架构，被很多人们所熟悉的移动SoC采用，
引入了很多新的关键特性，如可伸缩向量扩展 (SVE2)、可伸缩矩阵扩展 2 (SME2)、分支记录缓冲区扩展 (BRBE)等。

\subsection{RISC-V}
RISC-V 是一种基于 RISC 架构的指令集架构，支持多种指令集扩展。
RISC-V最早只是为给UCB并行计算课程做一个教学工具而开发的，然而今天已经成为
横跨汽车、数据中心、航天、AI的全球计算基石。
RISC-V架构的不同部分可以以模块化的方式组织在一起，用户能够灵活选择不同的模块组合，来实现自己定制化设备的需要。

\section{算法设计与实验对象说明}
\subsection{统一输入模式}
为保证两种 ISA 的实验完全可复现，本实验不再只使用单次长度为 $8$ 的向量，而是采用“固定 8 元模式 + 重复扩展”的方式生成更长输入向量：
\[
q_{\text{base}} = [1,2,3,4,5,6,7,8], \qquad
k_{\text{base}} = [8,7,6,5,4,3,2,1]
\]
两者单次 8 元点积结果为：
\[
1\times8 + 2\times7 + \cdots + 8\times1 = 120
\]
若向量长度为 $LEN$，且 $LEN$ 是 8 的整数倍，则单轮点积结果为：
\[
score_{\text{round}} = 120 \times \frac{LEN}{8}
\]
若外层重复执行 $REPEAT$ 次，则程序最终校验值为：
\[
score_{\text{total}} = score_{\text{round}} \times REPEAT
\]

\subsection{程序结构}
两份汇编都采用相同的总体结构：
\begin{Verbatim}[frame=single]
total_acc = 0
repeat_count = REPEAT

while repeat_count > 0:
    acc = dot(q, k, LEN)
    total_acc += acc
    repeat_count -= 1

if total_acc == EXPECTED_TOTAL:
    exit(0)
else:
    exit(1)
\end{Verbatim}

其中真正用于对比 ISA 差异的是 \texttt{dot\_loop} 这一层内层循环。外层重复主要是为了让程序执行时间更稳定、便于测量。程序结束时采用“内部比对校验值，正确则退出码为 0，错误则退出码为 1”的方式完成正确性验证，因此不再受退出码 0--255 范围的限制。

\subsection{读者在实验中应重点观察的指标}
为了保证“单一代表性差异”不被其他因素干扰，建议读者按优先级观察：
\begin{enumerate}
    \item \textbf{核心指标（必看）}：\texttt{dot\_loop} 的每轮静态指令条数、循环体字节数；

\subsection{步骤三：反汇编并定位核心循环}
\begin{Verbatim}[frame=single]

riscv64-linux-gnu-objdump -d riscv_dot > riscv_dot.dump
\end{Verbatim}

打开 \texttt{armv9\_dot.dump} 与 \texttt{riscv\_dot.dump} 后，搜索标签 \texttt{dot\_loop} 和 \texttt{dot\_loop\_end}。两者之间的指令就是本实验需要统计的核心循环体。读者应重点观察：
\begin{itemize}
    \item 每轮循环包含多少条指令；
    \item 哪些指令完成访存，哪些指令完成乘加，哪些指令完成循环控制；
    \item 某些操作是否被更强的单条指令融合。
\end{itemize}

\subsection{步骤四：记录代码密度与时间结果}
本实验的预期观察结果有三层：
\begin{enumerate}
    \item ARMv9-A 版本的内层循环更短，静态指令数更少；
    \item 在本机 WSL + QEMU User 6.2.0 的测量结果中，RISC-V 版本的平均模拟运行时间更短；
    \item 在同样环境下，本次测量中 ARMv9 SVE2 版本平均时间高于 ARMv9 标量版本。
\end{enumerate}

这两个结果并不矛盾。前者反映的是 ISA 在表达同一循环时的静态代码密度，后者反映的是当前模拟器实现与当前测试平台组合下的 wall-clock 时间。

\subsection{预期发现对应的指令集原理}
若读者按步骤完成实验，应能够将观察结果追溯到以下指令集层面的设计差异：
\begin{itemize}
    \item ARMv9-A（AArch64）可使用后索引访存（如 \texttt{ldr w4, [x0], \#4}），在取数同时完成地址更新；
    \item ARMv9-A（AArch64）可使用融合乘加指令 \texttt{madd}，将乘法与累加压缩到一条指令；
    \item RV64IM 在本实验约束下采用更细粒度的“访存/运算/更新”分解式指令序列，因此循环体更长。
\end{itemize}

\subsection{ARMv9-A（AArch64）核心循环}
\begin{Verbatim}[frame=single]
dot_loop:
    ldr  w4, [x0], #4
    ldr  w5, [x1], #4
    madd x2, x4, x5, x2
    subs w3, w3, #1
    bne  dot_loop
\end{Verbatim}

dot_loop:

    add  s0, s0, t4
    addi a0, a0, 4
    addi a1, a1, 4
    addi t0, t0, -1
    bnez t0, dot_loop
\end{Verbatim}

\subsection{结果解释}
从静态循环可见，ARMv9-A（AArch64）通过后索引寻址与 \texttt{madd} 指令，把“取数并更新地址”以及“乘法并累加”压缩到更少的指令中，因此在 \textbf{代码密度} 这一指标上明显优于 RISC-V。

进一步观察 ARM 标量与 ARM SVE2 对比可见，在当前 WSL + QEMU User 6.2.0 环境下，SVE2 版本并未体现更短的 wall-clock 时间，且在更大数据量时差距扩大。这提示读者：\textbf{向量指令优势是否可见，强依赖于运行平台是否真实支持并高效实现对应扩展。} 在模拟器环境中，SVE2 可能受到翻译与仿真开销影响。

同时，三组工作负载下测得的 wall-clock 时间仍表现为 RISC-V 更短。这说明：\textbf{静态指令数更少，并不自动等价于当前模拟器中运行更快。} QEMU User 的翻译策略、不同后端的 helper 实现、宿主机执行路径以及系统噪声都会影响最终时间结果。

因此，本实验得到两个可以同时成立的结论：
\begin{enumerate}
    \item 若评价标准是核心循环的静态指令条数与循环体大小，则 ARMv9-A 的代码密度更高；
    \item 若评价标准是本机 QEMU User 6.2.0 中的平均模拟执行时间，则本次测量中 RISC-V 更快；
    \item 在当前模拟环境中，ARMv9 SVE2 版本不比 ARM 标量版本更快。
\end{enumerate}

需要特别说明的是，第二个结论仅适用于当前模拟环境，不能直接外推为“真实 ARMv9 硬件一定慢于真实 RISC-V 硬件”。它更适合作为“代码密度结果和模拟运行时间结果可能分离”的一个实验观察。
